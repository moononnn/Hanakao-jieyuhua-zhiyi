# 解语花·知意

Hana v2 App 分享版，项目 ID：`jiegehua-zhiyi`。

知意的第一条纵向能力是“关键决策 Ask”：伙伴工作中遇到会实质改变行动、风险、成本或交付结果的分岔时，调用应用工具向用户展示结构化选择；模型按问题语义决定单选或多选（互斥方案单选、可同时成立的项目多选），并必须显式提交模式，避免遗漏时静默落成单选；多选答案会校验数量和选项。用户回答后，工具结果返回发起调用的原会话，伙伴再接着完成原任务。Ask 的选择只说明用户选了哪条方案，不自动授权外部或不可逆操作；执行前先核对是否已有针对具体动作及后果的明确授权，缺少时再另行确认。普通、低风险、可逆的小选择应由伙伴自行采用合理默认值。

## 当前实现边界

- 知意通过 Hana 固定整页入口打开，页面以设置分区呈现，不再作为画布悬浮卡展示；Hana 功能面板可只读查看当前权限状态，权限变更仍在 Hana 设置中完成。
- 悬浮球运行时，关键 Ask 在花球旁作答：单选点选即提交，多选先勾选再确认。球未运行或启动失败时，当前开发版会登记一条十分钟内有效的待办，让伙伴用知意 Recipe 将选项卡放进原会话消息流；用户点击会唤醒**新一轮对话**，伙伴须通过知意的绑定/核验工具校验卡片、会话与选项后才可继续原任务。配方卡无法展示时可回退 Hana 原生确认卡；无球正式交接尚待实机验收，不能称为完整通过。
- 这是一条可由模型调用的应用工具，需在 Hana「设置 → 应用 → 应用权限 → 解语花·知意」中授权「自动调用工具」，并为目标伙伴启用该 App。知意会在主模型生成前将简短 Ask 引导追加到系统提示词，不会作为聊天发言；「改写系统提示词或注入消息」是应用级权限，开启后会作用于所有经过该钩子的伙伴对话回合，暂不按伙伴分别限定，并增加少量主模型输入 token。另可从 Hana 已配置模型中指定 Ask 判断模型；授权「使用已配置的模型」后，只对所有会话里含明显选择线索的当前输入做一次预检，不读取历史聊天，这会额外消耗所选模型的 token，普通聊天不触发预检。设置页的「测试连接」会用短提示实际调用当前选择的模型，验证连通性并消耗少量 token，但不会保存选择；保存后按钮会显示「已保存」。无球的原生确认卡不需要「显示输入框上方的自定义界面」权限。
- 知意随 App 提供 `recipes/zhiyi-ask/` 配方源码与 `skills/zhiyi-ask-handoff/` 交接说明。当前 Hana 的 `show_card.template` 只解析已安装的全局 Recipe，**App 随包携带并不等于可直接发卡**；使用者还需通过 Hana 配方安装审核单独安装 `zhiyi-ask`。如果配方缺失，伙伴必须明确报告或走原生确认卡，绝不能假称用户已经看到题。App 内的配方源码与 Hana 全局已安装配方是两份文件，后续更新卡片逻辑时也要同步更新全局配方；已发出的旧卡不会热更新。卡片点击开启新回合，不恢复旧工具 Promise；App 进程重启会忘记未答待办，旧卡不可再视为有效。
- 推荐回复：知意已注册推荐工具，读取调用它的当前对话最近 8 条可见文字，隐藏思考不进入提示；默认跟随该会话使用的模型，也可在设置页选择 Hana 已配置的文本模型。设置页可调“要不要推荐”“每次都推荐 / 看情况推荐”“推荐几条”“推荐方向勾选”，改完即时保存。该时机与方向通过主模型生成前的系统提示词引导实现，伙伴在正文写完后自行判断是否出卡；看情况推荐时某些轮次没有卡片是正常的。推荐以**用户身份**出现，只做卡片展示，知意不替用户发送，卡片按钮目前是复制。**尚未迁完**：球内推荐面板、直接发送、自定义 API/Key/模型名、方向名的对话式修订。关闭推荐只是不再注入引导，工具本身仍在伙伴工具列表中。为取得会话内容与当前模型，需审核「读取其他会话」及「使用已配置的模型」权限；前者在宿主层允许读取 App 私有会话之外的其他会话，当前实现只访问工具调用绑定的当前会话，不枚举其他对话。
- 已复制旧版 PyQt6 悬浮球界面和 9 个 SVG 资源，并将 Ask 通信改为知意自己的本地回环桥；不再连接旧插件代理，也不读取 Hana 全局偏好文件。球状态写入知意专属 App 数据目录。
- 桌面悬浮球是可选体验，由设置页启动或收起；右键花球也可打开「关闭悬浮球」菜单。它当前只承载关键 Ask，旧球的推荐回复面板、续接、朗读、润色及发送方式入口会隐藏，尚未迁移。
- 启动球需要在 Hana「设置 → 应用 → 应用权限 → 解语花·知意」审核「运行外部程序」，并在本机安装 Python 与 PyQt6。Windows 上优先用 Python 启动器 `py.exe -3`，避免误选未安装 PyQt6 的其他 Python；只从 `HOME` 推导并传入当前用户的 `APPDATA` 路径，让默认 Python 找到用户级安装包。知意不会转发整份环境变量，也不会自动安装依赖。外部进程不继承 AppHost 的文件/网络细粒度限制。无球或启动失败时仍可使用 Hana 原生会话确认卡。
- 长回复速览：正文达到阈值（默认 600 字，可在设置页调）时，为这条回复生成最多三行要点，以引用块小卡的形式追加到**原文末尾**（`**速览** · 原文 N 字`）。原文在界面和会话历史里完整保留，位于速览上方；thinking 与工具片段不受影响。生成成功时，原文与要点会同时写入本机数据目录的 `long-replies` 归档；未触发或生成失败时不会写这份归档。速览模型可在设置页单独指定并测试连通，默认跟随 Ask 判断模型；请求最多使用 800 个输出 token，不强塞统一的思考档位。思考模型仍可能把预算用完或超时，失败时原文不变、速览不出现。大模型容易超时，12 秒仍拿不到结果就原样保留正文，速览不出现。用户明确要长文（小作文、详细展开、不要省略等）时不生成。
- 独立提示词优化、语音朗读和浮球提醒尚未实现；Ask 判断模型只读取含选择线索的当前输入做预检，不修改用户伙伴的身份或性格文件。
